# Official Hara runtime adapter

Hara Studio consumes the runtime archive generated by the canonical
`hara-lang/hara` repository's `scripts/build-studio-runtime` target. It does not
define a competing WASM ABI.

## Installation

```bash
# Build in hara-lang/hara
make studio-build

# Extract the generated tarball and install it here
npm run runtime:install -- /path/to/hara-studio-runtime-VERSION
```

The installer validates these minimum files before copying the archive:

```text
rust/hara.wasm
rust/hta.js
rust/hta-worker.js
rust/hta-shared-worker.js
rust/host/broker.js
rust/host/services.js
```

The full archive also contains Studio capabilities, HAL bootstrap code, UI
styles, examples, and demonstration assets.

## Browser adapter

`src/runtime/canonical.js` performs four steps:

1. Fetch `runtime/rust/hara.wasm` as bytes.
2. Import the official browser broker and host-service modules.
3. Create host services with the `studio/eval` capability.
4. Create and retain a kernel named `STUDIO`.

Evaluation maps to:

```js
broker.eval("STUDIO", source)
```

The adapter tracks the active namespace and prefixes REPL forms with an `ns`
form when needed. A file containing its own `ns` declaration updates that state.
Reset closes and recreates `STUDIO`, giving the user a clean kernel without
attempting to close the broker's reserved `ROOT` kernel.

## Runtime boundary

The UI's worker protocol deliberately remains smaller than the canonical
runtime API:

```text
boot · eval · load-file · inspect · reset
```

That lets the browser shell use either:

- the canonical Hara WASM broker, or
- the embedded development evaluator.

Future protocol additions should expose canonical concepts rather than inventing
parallel ones: kernel sessions, trace evaluation, disposable document previews,
filesystem mounts, program hosts, graphs, and capability grants.

## Values

The canonical runtime returns HTA-backed values such as keywords, symbols,
maps, sets, handles, and vars. Studio formats those values for the REPL while
retaining opaque results inside the worker for later inspection. Non-cloneable
host resources should remain handles and never be sent directly to the page.

## Fallback

When the runtime archive is not installed, `src/runtime/host.js` creates the
embedded evaluator. The fallback supports enough HAL to exercise the IDE:

- namespaces and vars;
- closures and variadic functions;
- arithmetic and common collection operations;
- stdout;
- `hta/render` and `preview/html` demonstration effects.

It is intentionally not presented as language conformance.
