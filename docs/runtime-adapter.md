# Official Hara runtime adapter

Hara Playground consumes the runtime archive generated by the canonical
`hara-lang/hara` repository's `scripts/build-studio-runtime` target. It does not
define a competing WASM ABI.

## Installation

```bash
# Build in hara-lang/hara
make studio-build

# Extract the generated tarball and install it here
npm run runtime:install -- /path/to/hara-studio-runtime-VERSION
```

The installer validates these minimum files before copying the archive:

```text
rust/hara.wasm
rust/hta.js
rust/hta-worker.js
rust/hta-shared-worker.js
rust/host/broker.js
rust/host/services.js
```

A Supersonic-complete archive additionally contains:

```text
rust/studio/supersonic.js
rust/studio/hal/supersonic.hal
```

The full archive also contains Studio capabilities, HAL bootstrap code, UI
styles, examples, and demonstration assets. Hara's Studio runtime archive CI
constructs the release-shaped tarball, verifies its SHA-256 file, and asserts
that the general and self-contained music runtimes contain the Supersonic
provider and namespace.

## Browser adapter

`src/runtime/canonical.js` performs these steps:

1. Fetch `runtime/rust/hara.wasm` as bytes.
2. Import the official browser broker and host-service modules.
3. Ask the page bridge for the Supersonic HAL namespace when
   `audio/playback` is granted.
4. Create host services with the available capability set, current session
   grants, and a plain-message Supersonic proxy.
5. Create and retain a kernel named `STUDIO`.

Evaluation maps to:

```js
broker.eval("STUDIO", source)
```

The adapter tracks the active namespace and prefixes REPL forms with an `ns`
form when needed. A file containing its own `ns` declaration updates that state.
Reset closes and recreates `STUDIO`, giving the user a clean kernel without
attempting to close the broker's reserved `ROOT` kernel.

## Project capabilities

Before `boot`, the page reads the canonical project descriptor and supplies its
normalized `:project/capabilities` vector. The worker always adds
`studio/eval`, rejects capabilities outside its available set, and supplies the
resulting session grants to the official host-service layer.

```text
project.edn request
  ∩ worker available capabilities
  = session grants
```

For Supersonic, the official host service performs the first capability check.
The page-side `PlaygroundAudioHost` repeats the check before accepting a
browser operation.

## Page host bridge

The canonical broker and HAL host services run in the runtime worker, while
browser resources stay on the page. The worker therefore sends a correlated
plain-message request:

```json
{
  "type": "host-call",
  "id": "host-1",
  "requestId": "request-4",
  "operation": "gw.audio.supersonic/update",
  "args": ["example/live", "transport", "tempo", 138]
}
```

The page dispatches only registered operations and returns one terminal message:

```json
{ "type": "host-result", "id": "host-1", "value": {} }
```

or:

```json
{
  "type": "host-exception",
  "id": "host-1",
  "error": { "name": "Error", "message": "audio/capability-not-requested" }
}
```

No browser resource crosses this protocol. The page provider owns localStorage,
`AudioContext`, oscillators, gains, intervals, and user-gesture state.

## Runtime boundary

The UI request protocol deliberately remains smaller than the canonical runtime
API:

```text
boot · eval · load-file · complete · inspect · reset
```

Host calls are a separate reverse channel initiated by canonical HAL code. This
lets the browser shell use either:

- the canonical Hara WASM broker, including declared host capabilities; or
- the embedded development evaluator, without pretending to support those
  canonical host capabilities.

Future protocol additions should expose canonical concepts rather than inventing
parallel ones: kernel sessions, trace evaluation, disposable document previews,
filesystem mounts, program hosts, graphs, and capability grants.

## Values

The canonical runtime returns HTA-backed values such as keywords, symbols,
maps, sets, handles, and vars. Playground formats those values for the REPL
while retaining opaque results inside the worker for later inspection.
Non-cloneable host resources remain handles or private page objects and are
never sent directly across the worker boundary.

Supersonic converts canonical HTA maps, vectors, keywords, and symbols into a
plain graph before sending the host call. Provider snapshots are converted back
to HTA-compatible values by the official host service.

## Fallback

When the runtime archive is not installed, `src/runtime/host.js` creates the
embedded evaluator. The fallback supports enough HAL to exercise the IDE:

- namespaces and vars;
- closures and variadic functions;
- arithmetic and common collection operations;
- stdout;
- `hta/render` and `preview/html` demonstration effects.

It does not implement `gw.audio.supersonic`, filesystem mounts, network calls,
or other canonical host services. It is intentionally not presented as
language conformance.
